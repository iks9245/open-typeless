# 主視窗：歷史紀錄、詞彙表與設定

## 目標

把主視窗從 Electron 範本的「Hello World」改成可用的介面，讓使用者不必改程式就能：

1. 瀏覽、搜尋、複製、刪除轉寫歷史
2. 編輯自訂詞彙表，並預覽實際送給 whisper 的提示句
3. 調整設定，並看到 whisper 伺服器的狀態

介面語言為繁體中文。

## 限制

- **主視窗同時負責錄音**：`renderer.ts` 在收到 ASR 狀態 `listening` 時啟動麥克風。錄音邏輯必須留在 React 之外，介面重繪、切換分頁、出錯都不能影響錄音
- 渲染程序只能透過 `window.api` 存取資料（`history`、`settings`、新增的 `whisperServer`），不得直接存取 Node 或 Electron
- 浮動視窗不變

## 1. 版面

- 視窗預設 960×680，最小 720×520，標題「Open Typeless」
- 頂部：app 名稱與三個分頁：**歷史紀錄**、**詞彙表**、**設定**
- 純 CSS，跟隨系統的淺色／深色模式，macOS 系統字型
- 可用鍵盤操作；按鈕與欄位有可見的焦點樣式；儲存結果用 `aria-live` 告知

## 2. 歷史紀錄

| 元素 | 行為 |
|---|---|
| 搜尋框 | 輸入後 300 毫秒查詢（`history.list({ query })`），比對插入的文字 |
| 狀態篩選 | 全部／完成／沒有文字／失敗 |
| 列表 | 每筆顯示：時間（今天顯示時:分，否則月/日 時:分）、文字（失敗時顯示錯誤原因）、狀態標籤、音訊長度、辨識延遲、插入結果 |
| 操作 | **複製**文字；**刪除**（行內二次確認，不用瀏覽器 `confirm()`） |
| 載入更多 | 依 `nextCursor` 載入下一頁，每頁 50 筆 |
| 清除全部 | 行內二次確認後呼叫 `history.clear()` |
| 即時更新 | 收到 `history.onChanged` 後重新載入第一頁（合併 300 毫秒內的多次事件） |
| 空狀態 | 沒有任何紀錄時，說明「按住右 Option 鍵開始聽寫」 |
| 歷史停用 | 設定 `history.enabled` 為關閉時，顯示提示與前往設定的連結 |

錯誤代碼對應的中文說明：`start_failed` 無法連線到 whisper 伺服器、`transcription_failed` 辨識失敗、`stop_failed` 結束錄音時出錯、`interrupted` app 在錄音中被結束。

## 3. 詞彙表

- 輸入框＋「新增」按鈕（Enter 也可新增），詞彙以標籤列出，每個都有移除按鈕
- 驗證（在介面上即時顯示原因）：不可空白、最長 40 字、不重複（不分大小寫）、最多 50 個
- 每次增刪立即儲存（`settings.update({ asr: { vocabulary } })`），顯示「已儲存」或錯誤
- 顯示計數「12 / 50」
- **提示句預覽**：顯示實際會送出的句子；超過 150 字而未送出的詞彙要標示出來
- 說明文字：詞彙表可提高專有名詞的辨識率，並讓結果傾向使用繁體中文

## 4. 設定

| 區塊 | 項目 | 控制項 |
|---|---|---|
| 語音辨識 | whisper 伺服器位址 | 文字欄位，失焦或 Enter 時儲存，需為 http(s) |
| | 語言 | 下拉：自動偵測、中文（zh）、粵語（yue）、英文（en）、日文（ja）、韓文（ko） |
| | 伺服器狀態 | 唯讀：模式（由 app 管理／接管／外部／不可用）、狀態（啟動中／就緒／已停止／失敗）、模型檔名、失敗原因。設定分頁開啟時每 3 秒更新 |
| 輸入 | 自動插入文字 | 開關 |
| 歷史紀錄 | 記錄歷史 | 開關 |
| | 保存錄音 | 開關 |
| | 保留天數 | 下拉：永久、7、30、90、365 天 |

- 開關與下拉變更時立即儲存；儲存失敗時還原並顯示錯誤
- 收到 `settings.onChanged` 時同步顯示

## 5. 需要的主程序變更

- **`whisper-server:status`**：新的唯讀 IPC，preload 暴露 `window.api.whisperServer.getStatus()`
  - 只回傳 `mode`、`state`、`reason`，以及模型、VAD 模型與伺服器程式的**檔名**（不含完整路徑與 PID），避免把使用者的目錄結構傳到介面
- **提示句產生函式移到 `src/shared/`**，讓主程序與介面使用同一份邏輯，預覽與實際送出一致

## 6. 驗證

### 自動化

- 純函式（時間格式、錯誤說明、詞彙驗證）的單元測試
- **主視窗 UI 測試**：在暫存 `userData` 中，以真正的 Electron 載入建置後的主視窗與 preload，預先寫入歷史資料，用 `executeJavaScript` 操作介面並檢查結果與資料庫：
  - 歷史列表顯示、搜尋、篩選、載入更多、複製、刪除、清除
  - 詞彙新增、驗證錯誤、移除、預覽句子、儲存到設定
  - 設定變更寫入、伺服器狀態顯示
- 對每個分頁截圖，由 Claude 檢視版面

### 錄音不受影響

- 現有整合測試全部通過
- UI 測試中確認：收到 `listening` 狀態時錄音器啟動的邏輯仍在（不需真的麥克風）

### 需要使用者

- 實際看過畫面，確認外觀可接受
